# 特殊站点认证与签到说明

部分站点和标准 new-api 的认证/签到流程不同，本页说明这些站点的差异化行为与配置方法。

## AgentRouter（agentrouter.org）

### 认证方式

- 推荐：浏览器 F12 → Application → Cookie → 复制 `session` 值，走「Session Token / Cookie」导入，并填写站点用户 ID（个人中心 URL 里的数字）。
- 该站使用 GitHub / LinuxDO 第三方登录，凭证续期走对应 OAuth 流程。

### 签到机制（与其他站点不同）

- AgentRouter **没有独立签到接口**（`/api/user/checkin` 不存在，返回 404）。
- 签到奖励只在**重新登录**时由服务端随新 Session 下发；单纯查询用户信息不会触发签到。

### 配置自动签到

1. 添加账号后，打开账号的「编辑」弹窗。
2. 在「签到重登录方式」中选择账号绑定的第三方登录来源（GitHub 或 LinuxDO）。
3. 在浏览器登录对应第三方站点（github.com 或 connect.linux.do），F12 → Application → Cookie 复制该站整段 Cookie，粘贴保存。
4. 之后每次签到会自动完成一次 OAuth 重新登录：
   - 获取 `/api/oauth/state` 并保留其会话 Cookie → 第三方授权跳转 → 将同源 `/oauth/{provider}` 页面回调转为 `/api/oauth/{provider}`，携带 state 会话领取新 Session；
   - 校验新 Session 归属的用户 ID 与本账号一致（不一致会丢弃新凭证，不会覆盖）；
   - 对比签到前后额度，只有真实增加才记为签到成功并显示奖励；
   - 新 Session 在身份验证成功后替换旧凭证；保留原 API Key 和账号别名，不在签到链路里追加无关令牌查询。

### 常见提示

| 提示 | 含义 | 处理 |
| --- | --- | --- |
| `github/linuxdo 登录态已失效…` | 第三方 Cookie 过期 | 重新登录第三方站点，F12 复制最新 Cookie 到「编辑 → 签到重登录」 |
| `需要重新点一次授权确认…` | 第三方要求重新授权该应用 | 浏览器里用该第三方账号重新登录一次 AgentRouter（同意授权）后再试 |
| `未配置签到重登录…` | 账号未配置重登录 Cookie | 立即返回配置提示，不发起上游请求；按上文完成配置 |

> 第三方会话的有效期由对应站点决定。站点要求重新登录或确认授权时，按提示更新 Cookie；保存配置不代表第三方会话已验证。

### 请求与身份校验

- 裸 Session 和整段 Cookie 复用导入规范化逻辑；读取签到前额度时也补齐 `session=`，避免把有效登录态当成缺少快照。
- `/oauth/github` 或 `/oauth/linuxdo` 是第三方实际返回的前端回调地址；它不是登录页。严格校验同源路径、授权码和 state 后调用 API 回调。
- 第三方 Cookie 只发给对应第三方域名；本站 state Cookie 只发本站。优先验证成功 OAuth 回调携带的用户 ID 和新 Session；回调提供有效额度快照时复用，缺字段或两个额度同时为默认零值时才补查 `/api/user/self`。若该路径刚触发滑块，保留余额并停止重复查询。回调 ID 不匹配直接停止，保留旧凭证。
- 单次网络请求 5 秒预算、整条 OAuth 链 25 秒预算；响应体也在预算内，并释放重定向响应。502、429、挑战页与未知页面分别说明，不统一误报 Cookie 过期。
- 奖励只用本次上游前后额度差；旧数据库额度不参与奖励计算，`checked_in=true` 也不直接换算金额。没有签到前快照，或回调明确未签到却出现额度增加时，保留已验证的新凭证和余额，奖励标为待确认。

## AnyRouter（anyrouter.top）

- 本部署使用 main 基础上的 HTTP 协议适配：登录前预热 `/login`，防护 Cookie 按站点和实际代理缓存，账号 Session 分开保存。
- 账号密码登录和 Session/Cookie 导入均不创建持久浏览器 Profile；运行容器不包含 Chromium、noVNC 或旧 Fork 浏览器签到模块。
- `Cookie: session=...; ...` 整段请求头、裸 Session 和复制产生的换行使用同一套规范化处理，保留值里的 `=` 和其他 Cookie。
- 非 JSON 的 HTTP 403 与真实挑战页分别报告；站点代理继续使用现有账号/站点配置，不自动切换共享代理节点。
- 签到使用 Any 专用 HTTP 流程：预热 `/login` → 校验 `/api/user/self` → 单次 `POST /api/user/sign_in` → 再读取同一用户额度。不会探测普通 NewAPI 的 `/api/user/checkin`。
- 只保留导入凭证的账号 Session；从当前出口重新取得 `acw_tc`、`cdn_sec_tc`、`acw_sc__v2`，按站点和实际代理线路隔离缓存。过期浏览器防护 Cookie 不会覆盖新值。
- 奖励取签到前后“剩余额度 + 已用额度”的实际差额，不信任响应中的 reward 或本地旧余额。零增长记为 skipped/+0；用户 ID 不匹配或额度字段缺失时停止操作。
- 旧账号缺用户 ID 时，只从现有 Session 的结构化 `id` 字段恢复候选，并通过 `/api/user/self` 验证；不拿 LinuxDO 用户名后缀当本站 ID，不枚举其他用户。已填写 ID 的账号继续严格匹配，出现冲突需核实后更正配置。
- 已确认的最新余额、已用额度和总额度直接落库，页面重载即可读取，无需再发一次余额查询。
- HTTP 429 或 ESA `http_ratelimit` 进入当前线路冷却，遵循 Retry-After（缺省 60 秒），期间不重复请求。不把限流、网关 HTML 或无新增额度误报为 CF、凭证过期或签到成功。
- 单次 HTTP 请求 5 秒预算；只读额度查询遇到超时/502/503/504 最多重试一次。限流和身份错误不重试；单账号签到总预算仍为 25 秒。
- 签到 POST 响应中断时只补查同一账号额度，不重放 POST；查到实际增长才记成功，未查到则标明结果待确认。
- 同时保留账号密码登录、Session/Cookie 导入和独立的后台保存流程。实站验证状态以本次运维记录为准，测试环境奖励不是实站发奖证明。

## 保存与同步

- 编辑账号先保存数据库并返回；令牌、模型和路由维护在后台执行，外站慢响应不再拖住保存按钮。
- 同账号连续保存会依次处理后台维护，后一次修改不会因任务合并丢失。
- 过期 API Key 只有验证成功后恢复 active；后台失败保留已经保存的新凭证，并记录同步失败。
- AgentRouter 的第三方 Cookie 和目标站点 Session 分开保存，修改一项不会清空另一项。

## 重复操作

同一账号的单次点击与批量签到共用进行中任务；请求未完成时复用结果，结束后释放，避免并发重复登录和重复写日志。

## 2026-09-16：Agent 登录成功被后置查询覆盖的修复

### 已定位的原因

- 实际 GitHub OAuth 链：state、授权、回调成功；回调含正确 ID、新 Session，随后请求 `user/self` 收到 HTTP 200 阿里云滑块，旧流程丢弃了已验证的登录结果。
- 站点自己的前端直接使用 OAuth 回调用户对象建立登录态；本部署现在将身份与余额分开处理：同源、state、身份正确即可保存新 Session，余额另行核验。实站还确认回调 DTO 会把 quota、used_quota 同时填为默认零值；该组合不作余额依据。
- 旧通用 NewAPI 管理回退在同一滑块 fixture 上，一次余额/令牌读取各发 18 次、模型读取发 20 次，包含其他用户 ID 探测。该请求放大已复现；其是否触发上游风控仍缺上游证据。

### 当前协议约束

- Agent 的身份、余额、令牌、模型、分组、令牌增删走专用 Session 请求；明确 ID 固定使用，缺 ID 只从结构化 Session 获取提示并向上游核对，不猜其他账号。
- 实站确认 `/api/user/self` 触发滑块时，`/api/token/` 和 `/api/user/models` 仍返回 JSON。导入允许至多一次同 Session/同 ID 的令牌列表校验，要求非空且所有 `user_id` 都匹配；空列表、缺 user_id、混合/其他 ID 均未通过身份校验。令牌额度永不当作账号余额。
- 管理请求按站点和有效代理串行；同路径滑块默认冷却 60 秒，429 遵循 `Retry-After`。冷却与账号 Cookie 分离，切换有效代理不会沿用其他线路的冷却，API Key 的模型接口也不被 `user/self` 的冷却拖住。
- 单次请求 5 秒，涵盖排队、连接和响应体；验证及需要两次 HTTP 的管理操作总预算 8 秒，取消后不在后台继续探测。令牌列表失败保留原凭证；空列表与错误页明确区分。
- Agent 的 API Key（包含无 `sk-` 前缀的 48 字符令牌）只发送 Bearer，不混入 Session Cookie。Session 验证成功后最多追加一次可选令牌读取。
- 导入直接使用适配器返回的滑块、非 JSON、ID 错误、超时分类，不再追加多组诊断请求；普通 SPA 的 `<script>` 不是防护证据。
- 登录完成但奖励待确认时，接口为 `success:false/status:skipped/rewardPending:true/credentialsRefreshed:true`，不带奖励金额；余额未核实则不返回 `balanceInfo`、不覆盖已有余额。UI 使用中性提示，日志不记假 `+0`，不发签到失败告警。
- 实际完成重登录后推进签到间隔，包含额度无新增和奖励待确认，防止调度下一轮马上重复重登；缺配置/验证失败不推进。普通 Any/NewAPI 的调度逻辑保持原样。
